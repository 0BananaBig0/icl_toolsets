# Independent vector scan returns

Support interface-free multi-bit and disjoint root ScanOutPorts, including vector OneHotScanGroup returns, when every static path for each output reaches one distinct ScanInPort bit and no graph vertex is shared between lanes. Preserve existing alias and gated same-path observations. Reuse the existing simultaneous chain scheduler, padding, state handling, copy and rollback semantics. Models with TAPs or effective ScanInterfaces continue to require explicit declarations; ambiguous endpoints, shared inputs/storage and independently controlled events remain unsupported.

Infer endpoints once in dependency order, O(V+E) endpoint-pass time/O(V) space, plus the existing O(R log R) root-map/ownership work for R roots, within the existing 4096-register/65536-vertex limits. Prove independence using CheckIndependentChains before enabling parallel mode. No new public API, ICL syntax, metadata, dependencies or RTL. The physical timing model remains the existing common virtual clock.

Acceptance: direct native hand-derived lane/state assertions (unequal lengths, offsets, copy, rollback), CLI original/flat/generated/reset replay with both one-hot branches and inversions, rejection and artifact preservation, and a representative 8-lane/8-branch run. Compare equivalent explicit-chain controls without claiming vendor certification or speedups. Existing Python/native suites, C++17/style checks, sanitizer, full normal regression, fresh unfiltered coverage and Rocky dynamic/static portability must be recorded. Preserve the strict 100% line/90% branch gate as failed if it remains unmet; this scoped feature does not complete project release acceptance. Fresh archive/install qualification is required for changed generator products; unchanged editor artifacts may reuse byte identity.
