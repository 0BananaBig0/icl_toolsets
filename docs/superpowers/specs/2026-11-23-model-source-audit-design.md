## Smallest complete change

1. Extend the existing empty-body semicolon rule in
src/pattern/pattern_flatten.cc from DataRegister/ToClockPort to all empty
To* port declarations. Preserve the existing spelling for other empty ports;
attributes/properties/explicit and inferred Source statements retain bodies.
Do not invent explicit Sources to hide virtual or scope-dependent defaults.
Test standalone and hierarchical default controls, all supported To* kinds,
attributes, root/child defaults and canonical flat/native state behavior.
Actual nonempty PDL must still replay source/flat/generated byte-identically.

2. In src/pattern/pattern_netlist.cc, replace the unchecked initial RefEnum
node_ids.at lookup with a checked scoped lookup and a missing-enum diagnostic.
Preserve existing kind/width rules, forward declarations, namespace and
instance specialization, declared names/case, and valid symbolic reset/default
values. Errors carry node origin/name/RefEnum name through the current
Connect diagnostic boundary. No broad exception swallowing or guessed enum.

3. Add one batch native model inventory support executable under
tests/src/pattern/pattern_netlist_inventory.cc, reusing public Design,
Elaborate and SerializeIcl. Given file arguments it loads each once, visits
effective module keys as explicit qualified tops, and emits one JSON record
per file with module results. Stages distinguish load, elaboration,
serialization, flat-load, flat-elaboration and canonical comparison. Catch
expected per-module source failures so other modules can be audited; failed
file reads/protocol/setup are process errors. Output success requires actual
canonical flat byte equality, not input-derived expected values. No scheduler,
solver, hardware replay, new public product API or new dependencies.

4. Add tests/src/pattern/audit_model_corpus.py consuming an existing fresh
tests/audit_icl_corpus.py report, the model inventory executable, and a checked
expectation registry tests/cases/model_source_acceptance.json. The registry
pins1016 required canonical module identities (1004 existing+12 corrected
empty-To ports) and56 currently unsupported serialization identities with
specific reasons. Module identities are relative corpus file plus effective
qualified module key; never confuse same-named modules in different files,
scopes, namespaces, or ordered overrides.

The script validates report inputs against current corpus hashes, invokes one
batch native subprocess, validates complete per-file/module protocol and
produces a fresh review-only JSON report with all actual stages, current
hashes, timing and counts. It returns failure for missing/failed required
canonical identities, unlisted serialization/flat/canonical failures,
unlisted or changed unsupported boundaries, raw internal map::at errors or
incomplete/unreadable subprocess output. Known unsupported cases remain
visible, never counted as canonical success. Ordinary nonrequired original
elaboration failures are reported without pretending invalid grammar examples
are runnable models. Improvements beyond a declared unsupported boundary
require a deliberate registry update, not silent evidence drift.

No per-module process, full-corpus rescan per module, new dependency, arbitrary
resource-limit increase, external source rewrite or hand-written flat model.
Reuse existing corpus manifest/import hash helpers and build patterns. All
new scripts/tests stay under project-root tests/ and mirror affected source
paths. Temporary evidence lives only in owned build/ or /tmp.
