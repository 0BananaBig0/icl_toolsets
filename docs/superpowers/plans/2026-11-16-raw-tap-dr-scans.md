# Raw TAP DR Scans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Known-binary raw DR for one currently active full modeled register.

**Architecture:** Reuse bound TAP qualification, existing hardware Active query,
ordinary Apply on a copy and exact one-CSU proof shared with raw IR.

**Tech Stack:** Existing C++17/Tcl/Z3/Python; no dependencies.

**Spec:** docs/superpowers/specs/2026-11-16-raw-tap-dr-scans-design.md

## Global Constraints

One bound scalar root TAP, one full pre-CSU ScanRegister, known SI. No implicit
IR/child retargeting or new FSM/clock/reset/solver engine. Existing limits stay.
Mixed raw IR/data rejects explicitly; kind-specific queue keys preserve it.
All new scripts under project tests/; serialize local and remote heavy work.

## Review Focus

- Active observation must ignore0 entries, reject x and multiple active registers.
- Exact DR proof cannot allow implicit IR setup, partial path or additional CSU.
- IR/data kinds must not overwrite each other silently in one queue.
- Stable/post-route and assigned pre-route footprint must be transactional.
- SO cannot control SI fill or owner/partial written history.
