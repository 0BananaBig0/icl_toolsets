# PDL tools implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver and install dynamic/static pdl-format and pdl-lsp.

**Architecture:** Tcl parsing feeds a separate source-preserving PDL tree and
semantic model, shared by both PDL executables. Language adapters reuse CLI I/O
and LSP infrastructure while retaining distinct ICL and PDL front ends.

**Tech Stack:** C++17, Tcl 8.6+/9 parsing API, GNU Make, Python unittest.

**Spec:** docs/superpowers/specs/2026-10-23-pdl-tools-design.md

## Global constraints

- Google C++ style; no source evaluation; no generated artifacts tracked.
- Separate ICL/PDL grammar, keyword sets and ASTs.
- New test scripts live under tests/ and mirror tested source paths.
- Default indent 2, supported widths 1–16; exit codes 0/1/2.
- Dynamic and fully static variants; never substitute stub Tcl for real Tcl.

## Review focus

- Braced data and quoted multiline values must retain their bytes/meaning.
- Nested script bodies and command substitutions must be checked without execution.
- Incomplete documents must provide diagnostics and useful local completion.
- Namespace/module collisions must not produce guessed navigation results.
- Existing ICL builds, packaging and editor behavior must retain regression parity.
