# Write Callback Endpoint Readback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Observe actual modeled endpoint transactions inside explicit write callbacks.

**Architecture:** Add actual read-callback invocation provenance to the existing operation
stream; replay supported write-body endpoint operations in the independent readback
scheduler while masking abstract callback storage to unknown.

**Tech Stack:** Existing C++17 Runtime/scheduler/readback/CLI, Tcl and Python3 unittest.

**Spec:** docs/superpowers/specs/2026-11-23-callback-endpoint-readback-design.md

## Global Constraints

- Actual logical callback-register observations, invoked ReadCallBack histories,
  physical callbacks, automatic dispatch/mixed caller/merge/timing expansion remain unsupported.
- Never turn requested callback data, expected reads or logical postconditions into
  actual observations; explicit manual history assumptions retain their semantics.
- Preserve canceled read requests (including inside a write body) and existing
  invoked-read inner-reset rejection, error poisoning, scope/reservation and source replay.
- Use existing Assume, scoped call execution and limits; no dependencies.
- Index callback membership once; no per-operation full-model scan or per-bit replay.
- New maintained tests under tests/src/pattern/;117stashes/unrelated worktrees preserved.
- Normal64/256/1024targets/fourgroups, three repeats/source-flat-generated <=10s/512MiB;
  SAN64/fourgroups same bounds. Matched callback-free/unused/observer-off controls;
  existing1024normal callback budget and16Kwide-alias256MiB bound unchanged.
- Full14native/14leakSAN, both whole generators, normal/selectedSAN corpus+producer/
  protocol/Make, changedC++quality, source packaging and measured controls.
- One fresh final independent review, one Critical/Important test-first fixpass,
  deferMinors/no rereview. Coverage1 excluded; broad4/6 remains pending.

## Review Focus

- A reset in an invoked read callback must never erase unsupported provenance.
- A read callback queued and canceled in a write body must remain uninvoked.
- Generated/split-file replay and mixed aliases must not reintroduce logical assumptions.
- A no-op callback cannot fabricate observed data or mismatch counts from <D>.
- Ordinary endpoint histories/scopes/status and callback-free performance remain intact.
