# Handwritten syntax edge cases

These 72 fixtures are constructed from IEEE 1687-2014, not copied from a vendor
or generated by a grammar fuzzer. They supplement a corpus that already reaches
every Bison production and Flex rule. There are **33 accepted inputs and 39
rejected inputs across 15 blocks**. Expected outcomes and printed/PDF page
references are maintained in [`../../conformance.json`](../../conformance.json).

The tests exercise the actual parser, formatter and LSP. Accepted inputs must
preserve tokens/comments/string contents and remain identical after a second
format. Rejected inputs must exit 2, print a diagnostic and produce no formatted
output. Every manifest entry also goes through versioned edits to a live LSP.
These are syntax and local validation fixtures, not elaborated hardware designs;
callback procedures and external BSDL entities are outside the ICL fixture.

## What each group protects

| Directory | Accept / reject | Boundary or recursive combination |
|---|---:|---|
| `enum` | 4 / 4 | 96- and 127-bit decimal limits; truncation of zero/unknown bits versus a set bit in a partial hex nibble; 96-bit concatenations versus a 95-bit member |
| `lexical` | 8 / 13 | Three-part number tokens, comment separators, consecutive/trailing underscores, longest-match suffixes, quote escaping, multiline string concatenation, nested arithmetic indices |
| `logic_signal` | 3 / 3 | Unknowns nested inside comparison RHS versus ordinary Boolean operands; reductions composed with Boolean operators; nested integer versus based-number arithmetic |
| `scan_mux` | 1 / 1 | Concatenated codes separated by `\|`, comments at alternatives; `\|\|` is not a selection separator |
| `data_mux` | 1 / 1 | Alternatives with sliced/inverted source concatenations; missing final code |
| `clock_mux` | 1 / 1 | Ordered alternatives followed by an unknown-bit fallback; `^` is not a selection separator |
| `data_register` | 3 / 3 | Parameterized callback module/subnamespace/procedure, adjacent argument tokens, double inversion; split markers, extra namespace depth, triple inversion |
| `to_clock_port` | 2 / 2 | Comments between period and unit and around frequency factors; identifier suffixes and comments splitting a unit |
| `parameter` | 2 / 2 | Forward references through string and numeric chains; mixed-type concatenation and fixed-width overflow |
| `access_link` | 2 / 3 | Nested opaque bodies with quoted/commented braces followed by standard syntax, including a new module; malformed normal tokens after leaving Generic mode and an unterminated nested string |
| `alias` | 2 / 2 | Multi-level hierarchy with slices/inversion and concatenated end-state values; a comment inside a path and unknown end-state bits |
| `data_out_port` | 1 / 1 | Child-port slices with parameterized indices; forbidden multi-level non-Alias reference |
| `instance` | 1 / 1 | Namespace-qualified module, parameter override and inverted input concatenation; extra module qualification |
| `scan_interface` | 1 / 1 | Keyword chain names with concatenated defaults; a Chain nested inside another Chain |
| `one_hot_data_group` | 1 / 1 | Nested addressable register and instance; selectable register in an addressable group |

For example, changing a numeric regex to accept every alphanumeric suffix would
incorrectly accept `number_illegal_suffix.icl`; disallowing comments between base
and digits would reject `number_comment_separators.icl`. Dropping recursive
unknown-bit tracking would accept `nested_unknown_outside_comparison.icl`.
Failing to leave Generic scanning mode would accept or consume invalid text in
`generic_then_bad_literal.icl`. The expected results are literal manifest values,
not computed using the parser under test.

`number_comment_separators.icl` retains the existing project interpretation of
size/base separation: §6.3.4 convention 12 permits whitespace around an
apostrophe, §6.3.5 defines `size` and `UNSIZED_HEX_NUM` separately, and §6.3.8
describes three tokens. However, §6.3.8(a) also says the size is “immediately
followed” by the apostrophe. This is an acknowledged wording ambiguity, not a
new portability guarantee. The previous ruling is recorded in
[`docs/icl-conformance-review.md`](../../../../docs/icl-conformance-review.md).
An apostrophe and its base letter remain indivisible in both interpretations.

## Parameter-width diagnostic regression

[`../diagnostics/parameter_width_overflow.icl`](../diagnostics/parameter_width_overflow.icl)
originally reproduced a missing check: WIDTH resolves through BITS to8, while
`$WIDTH'H1_FF` needs nine bits. The shared driver now resolves literal default
values and alias chains, so this is an ordinary negative conformance fixture.
The LSP regression verifies the diagnostic and clears it after BITS changes to9;
there is no expected-failure annotation. The fixed-width counterpart remains
`parameter/literal_width_overflow.icl`. Compound/instance-dependent widths still
require elaboration; see [the width fixtures](../parameter_widths/README.md).

## Run

From the repository root:

```sh
python3 tests/src/test_icl_conformance.py --binary build/icl-format --block enum
python3 tests/src/test_icl_conformance.py --binary build/icl-format
python3 tests/src/test_icl_diagnostics.py --binary build/icl-lsp -v
make check-dynamic BISON=/usr/bin/bison -j4
```

`--block` selects both existing and new cases for that block. The manifest,
live diagnostics, grammar coverage and corpus uniqueness checks discover these
fixtures without another runner or a build-system change. Metamorphic variants
and tool reports remain ignored under `tests/generated/` and `build/`.
